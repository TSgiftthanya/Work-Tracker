# Work Tracker — System Architecture

ระบบติดตามงานสื่อสาร (CPALL / 7‑Eleven internal communication tracker). Single‑page web app
เสิร์ฟด้วย Python stdlib HTTP server บน `localhost:8787` และรันเป็น macOS LaunchAgent
`com.local.worktracker`.

## 2. Build / dev workflow

Source lives in `src/`; `build.py` assembles `index.html` from `src/index.template.html` + the module
files. The server injects `<!--WT_BOOT-->` (user + state) at serve time.

**Deployed mode = EXTERNAL:** `index.html` (~79KB) references `/assets/js/*.js` and `/assets/css/*.css`,
which `server.py` serves from `src/` via the `/assets/` route (`Cache-Control: no-store`, path‑guarded).

```bash
# edit a module, e.g. src/js/19-team-leave.js, then:
python3 build.py             # regenerate index.html (external refs)  → reload browser
python3 build.py --check     # verify index.html == a fresh external build (sha256)
python3 build.py --inline    # OPTIONAL: one self-contained index.html (byte-identical to pre-split)
```

External `<script src>` (no defer/async) execute in document order — identical to the inline version.

`index.html` is a **static** file (browser‑cached is disabled by server: `Cache-Control: no-store`).
Changing it needs only a browser reload. `server.py` changes need a service restart:

```bash
launchctl kickstart -k gui/$(id -u)/com.local.worktracker
```

Revert to a known‑good build: `cp _dev/backups/index.bak75.html index.html` (bak75 = pre‑split baseline).

> ⚠️ Module scripts are **classic scripts** (not ES modules) and share one top‑level lexical scope:
> top‑level `let/const` in `00-core-main.js` (e.g. `people`, `tasks`, `render`, `statuses`) are visible
> to later modules. **Load order matters** — keep the numeric prefixes; `00-core-main.js` must stay first.

## 3. Runtime model

- **No DB server.** `window.localStorage` is shimmed (in `<!--WT_BOOT-->`) so every key write becomes
  `POST /api/state?key=…` (read‑modify‑write under a server `STATE_LOCK`), persisted to `data/data.json`.
  On load the server injects `window.__WT_STATE__`; the shim serves reads from it.
- **Members have no numeric ID** — the member *name* string is the ID, shared across Task Board,
  Team Performance, Communication Plan, and Team Leave.
- **Auth:** cookie token; users come from a Google Sheet or demo list. `window.__WT_USER__ = {name,team,role}`.

## 5. Cross‑feature data flow

- **Master Data → Task Board:** `window.DDget(key)` feeds task‑modal dropdowns; `DDsync()` reassigns
  live `people` + calls `render()` so edits reflect everywhere immediately. `window.DDdetail(media)`
  feeds the per‑type detail dropdown; Supporting Creator multi‑select reads `DDget('supporting')`.
- **Communication Plan ↔ Task Board:** "＋Task" → `createTaskFromCP` creates a board Task with
  `commId`, sets `record.taskId` (CP row kept). Board cards with `commId` show a "📅 Weekly Plan" tag.
  **Two‑way status sync:** `window.cpSyncLinked()` (called in renderCP + on board drop/modal‑save)
  keeps the CP record status = linked Task status; editing CP status pushes to the Task.
  Deleting a Task clears the CP `taskId` (self‑healing).
- **Team Performance / Dashboard cards:** share one renderer `window.wtRenderTP(S,tableId,metaId)`
  over `tasks` (independent per‑card state: view / orient / members / date range).
- **Automation owner perf:** media‑type columns computed from `tasks[].types[]` via `_cmMedia`.
- **Communication Manager report (`window.cmReport`):** aggregates tasks + channel records + CommPlan
  + Leave into an executive summary + rule‑based insights; Copy = chat‑ready text, Download = HTML.
- **Team Leave:** members from `DDget('people')`; capacity/quota/conflict all computed from the
  leave store; independent of tasks.

## 6. Server API (server.py)

- `GET /`                 → index.html (auth required; injects user+state; `Cache-Control: no-store`)
- `GET /login`            → login.html
- `GET /assets/js/*.js` · `/assets/css/*.css` → static module files from `src/` (public, no-store, path‑guarded)
- `GET /api/state`        → full data.json
- `POST /api/state?key=…` → set one key (read‑modify‑write under STATE_LOCK)
- `DELETE /api/state?key=…` → remove one key (or all)
- `POST /api/login` · `/api/logout` · `/api/refresh-users` · `/api/config`
- `POST /api/preview-data` · `POST /api/raw-sheet` → read a Google Sheet (gviz/export CSV;
  `raw-sheet` accepts `mode:internal|external` to pick the tab by name) — used by the CP import wizard
- `POST /api/import-data` → import media‑plan rows into tasks
- `POST /api/line/*`      → LINE config / send / quota notify

Google Sheets are fetched **anonymously** by the server, so a source sheet must be shared
"anyone with the link" to be importable.
