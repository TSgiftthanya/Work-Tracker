# Work Tracker

Internal communication/work tracker (CPALL / 7-Eleven). Single Python stdlib HTTP
server that serves a static SPA (`app/index.html` + `app/src/assets`) and a small
`/api` for shared state. **No external Python dependencies.**

> ⚠️ Do not hand-edit `app/index.html` — it is generated by `app/build.py` from `app/src/`.

---

## Local development

```bash
cd app
python3 build.py        # regenerate index.html from src/ (after editing src/)
python3 server.py       # serves http://localhost:8787  (WT_HOST/WT_PORT env)
```

Data persists to `data/data.json` (git-ignored). On first run, demo users are
seeded and a signing `secret` is auto-generated in `data/config.json`.

---

## Deploy to Render (UAT)

The app writes to disk, so it needs an **always-on instance with a persistent disk**
(Render **starter** plan — the free plan sleeps and has no disk).

1. Push this repo to a **private** GitHub repository (see below).
2. Render → **New → Blueprint** → connect the repo → Render reads `render.yaml`
   (Docker web service + 1 GB disk at `/var/data` + `WT_DATA_DIR`/`WT_HOST` env).
3. Confirm the **starter** plan and **Apply** → first build & deploy runs.
4. Public URL: `https://worktracker-uat.onrender.com` (name may vary).
5. **Auto-deploy**: every push to the connected branch redeploys automatically.

### First-boot accounts
On an empty disk the server seeds demo accounts and generates `secret` automatically,
so login works immediately. To add your real UAT team, either:
- use the in-app admin page **สิทธิ์ทีม** to import users from a Google Sheet, or
- edit `users.json` on the disk via **Render → Shell** (use `seed/users.example.json`
  as the shape; set each `code` to a real test password).

Access is limited by the app's own login — anyone with the URL only reaches the
login page and cannot enter without an account.

## Updating the live site

```bash
cd app
# edit files under app/src/ ...
python3 build.py            # rebuild index.html
python3 build.py --check    # verify (sha256 MATCH)
cd ..
git add -A && git commit -m "your change" && git push
# Render auto-deploys the new version
```

## Security

The following are **git-ignored and never committed** (they live only on the
server's persistent disk): `data/` (all live data), `data/config.json` (the HMAC
`secret`, any LINE token), `data/users.json` (user passwords), and `*.log`.

Keep the repository **private**. Rotate the `secret` only via the server (deleting
`config.json` regenerates it, which invalidates existing sessions).

---

## Known limitations (UAT)

- Shared state is one JSON file guarded by a server lock — safe from corruption, but
  concurrent edits to the **same** data key can overwrite each other (last write wins).
- No real-time push; other users see changes on refresh.
- For full concurrency + real-time, migrate the state layer to a shared DB (e.g.
  Supabase) as a later phase — not required for UAT.
